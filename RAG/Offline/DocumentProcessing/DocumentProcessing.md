## 2. Parsing

| 文档形式                             | 难点                                                         | 解决方案                                                     |
| ------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| PDF                                  | 一个典型的 PDF 可能包含多层嵌套表格、分栏排版、页眉页脚、内嵌图片、扫描版文字等。PDF 的底层通常更接近页面上的文字片段及其坐标，而不是具有完整语义结构的段落。通用解析工具可能导致表格被打散、分栏内容交错、阅读顺序错乱、页眉页脚混入正文；双栏论文中的正文和脚注也可能被错误拼接。 | 布局识别： 根据文本坐标、字体和页面布局恢复阅读顺序，区分标题、正文、表格、图片、页眉页脚等区域。表格提取： 使用 Camelot、pdfplumber 等工具提取表格；复杂表格可使用布局分析或专门的表格识别模型，并尽量保留行列关系。扫描页处理： 对图像型页面执行 OCR，并进行纠错。结构归一化： 转换为 Markdown、HTML 或统一的文档中间表示，同时保留页码、标题层级和元素类型。 |
| Word（DOCX）                         | DOCX 本身包含段落、标题样式、表格、列表、超链接、图片、脚注、批注等结构，但简单地提取纯文本会丢失这些信息。表格中的行列关系可能消失，编号列表可能失去层级，跨页表格可能被拆开；图片中的文字、图表说明和正文之间的关联也可能丢失。 | 结构化提取： 使用 python-docx、Mammoth 等工具读取段落、标题、列表和表格，避免只提取纯文本。保留层级： 根据标题样式、编号和缩进恢复章节结构与列表层级。表格处理： 将表格转换为 Markdown/HTML，并保留表头、合并单元格等重要关系；复杂表格必要时单独解析。多模态元素处理： 提取图片、图表和相关说明，必要时使用 OCR 或视觉模型识别内容。统一表示： 输出带有章节路径、元素类型等元数据的中间格式。 |
| PPT（PPTX）                          | PPT 的信息通常依赖空间布局，而非连续文本。标题、正文、文本框、图片、图表、箭头和连线之间可能存在语义关联。直接提取文本容易打乱阅读顺序，丢失图表中的数据、流程图的连接关系，以及跨页幻灯片之间的上下文。演讲者备注也可能包含正文没有的信息。 | 按幻灯片解析： 使用 python-pptx 等工具提取每页标题、文本框、表格、图表及备注，并保留幻灯片编号。布局恢复： 根据文本框坐标、层级和空间位置判断阅读顺序及内容分组。图表处理： 优先提取底层数据；无法直接提取时使用 OCR 或视觉模型解析。关系保留： 对流程图、架构图等保留节点与连线关系，必要时转换为结构化描述。上下文关联： 保留幻灯片标题、页码及相邻页面信息，避免单页内容脱离演示主题。 |
| Excel（XLSX）                        | Excel 的语义不仅存在于单元格文本中，还存在于行列位置、表头层级、公式、数值格式、合并单元格、工作表名称和单元格之间的关系中。直接按行转为文本可能丢失表头与数值的对应关系；多个工作表之间可能存在关联；公式单元格还涉及公式本身与计算结果的区别。大型工作簿也可能包含大量无关空白区域。 | 按工作表解析： 使用 openpyxl、pandas 等工具读取各工作表，并保留工作表名称、行列坐标和表头。恢复表结构： 识别多级表头、合并单元格、单位、注释及数据区域，将数据转换为结构化表格或带字段名的记录。公式处理： 根据需求同时保留公式与缓存计算值；注意公式结果可能因缓存缺失而无法读取。语义增强： 将表格标题、时间范围、单位、字段定义和来源作为元数据。检索优化： 小型表格可转换为 Markdown；大型表格更适合保留为结构化数据，按行、实体或业务主题建立索引，避免机械地按固定字符数切块。 |
| 图片（PNG、JPG 等）                  | 图片本身不一定包含可直接提取的文本。信息可能以截图、信息图、图表、流程图、架构图或照片的形式存在。OCR 可以识别部分文字，但难以独立理解图形关系、图表趋势、箭头指向和文本与视觉元素之间的对应关系。低分辨率、倾斜、复杂背景和小字号还会降低识别准确率。 | 先判断内容类型： 区分纯文本截图、表格、图表、流程图、自然图像等。OCR： 使用 PaddleOCR、Tesseract 等提取文字，并进行去噪、旋转校正和识别结果纠错。视觉理解： 对图表、流程图、架构图等使用视觉语言模型（VLM）生成结构化描述，必要时提取图例、坐标轴、节点及连接关系。关联上下文： 保留原图、图片标题、图注、所属章节及来源文档。索引设计： 可同时保存 OCR 文本、图像描述和原图引用，支持文本检索与多模态检索。 |
| HTML、Markdown                       | HTML 可能包含导航栏、广告、页脚、脚本、隐藏元素等噪声；直接提取全部文本会将无关内容混入正文。Markdown 虽然具有标题、列表、代码块和表格等结构，但代码块、嵌套列表、链接及表格的边界如果处理不当，也会丢失语义。网页中的正文、图片、表格和链接还可能存在引用关系。 | 正文抽取： HTML 使用 BeautifulSoup、trafilatura、Readability 等方法提取正文，去除导航栏、广告和其他模板噪声；必要时先执行 JavaScript 渲染。保留结构： 提取标题层级、段落、列表、表格、链接、代码块及图片说明。Markdown 解析： 使用 Markdown AST 或结构化解析器识别不同元素，避免把代码块和表格简单当作普通文本。链接与元数据： 保留标题、URL、来源、发布时间等可用信息，并关联正文引用的图片或附件。 |
| 扫描件（扫描版 PDF、纸质文档扫描图） | 扫描件本质上是页面图像，而非可直接提取的数字文本。除了 OCR 识别错误，还可能出现倾斜、模糊、印章遮挡、手写内容、多栏排版、表格线干扰等问题。即使单个字符识别正确，阅读顺序、表格结构、段落边界和页间内容也可能恢复错误。扫描版 PDF 还可能混合具有文本层的页面与纯图像页面。 | 预处理： 进行图像去噪、倾斜校正、方向检测、对比度增强及分辨率优化。OCR 与布局识别： 使用 PaddleOCR、云端文档解析服务或支持布局分析的 OCR 模型，识别文本区域、阅读顺序、表格和标题。后处理纠错： 利用词典、领域术语、格式规则及上下文检查纠正识别错误；对关键数字、日期、编号等重点校验。表格与复杂版面： 使用专门的表格结构识别或文档视觉模型。质量控制： 对低置信度结果进行抽样复核或人工校正，并保留页码、区域坐标及原图引用。 |



## 3. Cleaning

规则过滤：用正则匹配常见的噪声模式（页码、版权声明、导航链接），直接过滤 

去重：对文档做去重（SimHash、MinHash），避免重复内容占据检索空间 

质量打分：对每个文档块做质量打分（长度、完整性、可读性），低分的不入库

### 实践代码示例

```
import pymupdf  # Fitz for PDF
from docx import Document
import html2text
import re

class DocumentParser:
    def __init__(self):
        self.clean_patterns = [
            r'\s{3,}',  # 多余空格
            r'[\x00-\x08\x0b\x0c\x0e-\x1f\x7f-\x9f]',  # 控制字符
            r'^第[一二三四五六七八九十\d]+\s*[章节条].*$',  # 冗余标题
        ]

    def parse_pdf(self, file_path: str) -> str:
        """解析PDF，保留章节结构"""
        doc = pymupdf.open(file_path)
        text = ""
        for page in doc:
            # 提取带结构的文本
            blocks = page.get_text("dict")["blocks"]
            for b in blocks:
                if b['type'] == 0:  # 文本块
                    for line in b["lines"]:
                        for span in line["spans"]:
                            text += span["text"] + " "
                    text += "\n"
        return self._clean_text(text)

    def _clean_text(self, raw_text: str) -> str:
        """应用清洗规则"""
        cleaned = raw_text
        for pattern in self.clean_patterns:
            cleaned = re.sub(pattern, ' ', cleaned, flags=re.MULTILINE)
        # 合并换行，保留段落分隔
        cleaned = re.sub(r'\n\s*\n+', '\n\n', cleaned)
        return cleaned.strip()

# 使用示例
parser = DocumentParser()
content = parser.parse_pdf("企业年报.pdf")
print(f"解析并清洗后字符数: {len(content)}")
                    
```

## 5. Metadata

为每个文本块附加结构化元数据，增强检索的精准度和可解释性。

### 元数据分类

#### 文档级元数据

- 文档ID、文件名、来源系统
- 作者、创建/修改时间
- 文档类型、总页数、语言
- 安全等级、业务部门

#### 块级元数据

- 块ID、在文档中的顺序
- 起始/结束页码、行号
- 所属章节标题、段落类型
- 实体信息（人名、组织、关键词）

#### 系统级元数据

- 处理流水线版本、时间戳
- 嵌入模型版本、分块参数
- 校验和、质量评分

## 6. 增量更新

增量更新要解决三个问题：哪些文档变了？变了的部分怎么更新？旧的版本怎么处理？ 

哪些变了：用文档的元数据（更新时间、版本号）做变更检测，或者对文档内容做哈希比对 

变了怎么更新：不能全量重建（太慢），要做增量更新——只重新处理变更的部分，替换向量库 中对应的向量 

旧版本怎么处理：有些场景需要保留历史版本（如合同变更追溯），有些可以直接覆盖
